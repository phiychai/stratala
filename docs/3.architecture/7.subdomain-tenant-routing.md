This guide explains how to set up subdomain-based tenant routing for Payload CMS admin access.

## Overview

The system supports tenant-specific Payload CMS admin access via subdomains:

- **Main domain**: `localhost:3000/admin/cms` - Admin access to all content
- **Tenant subdomain**: `username.localhost:3000/admin/cms` - Tenant-specific content only

## Architecture

### Components

1. **Subdomain Detection Middleware** (`server/middleware/subdomain-tenant.ts`)
   - Extracts username from subdomain
   - Stores tenant context in event context

2. **Tenant Context Utilities** (`server/utils/tenant-context.ts`)
   - Resolves username to Payload user ID
   - Provides tenant context helpers

3. **Tenant-Aware Proxy** (`server/routes/admin/cms/[...].ts`)
   - Proxies Payload admin requests
   - Filters content by tenant automatically

## How It Works

### 1. Subdomain Detection

When a request comes in:
- `username.localhost` → Extracts `username` as tenant
- `localhost` → No tenant (main domain)

### 2. Tenant Resolution

1. Extract username from subdomain
2. Resolve username to Payload user ID via AdonisJS API
3. Cache result in event context

### 3. Payload Access Control

Payload's built-in access control automatically filters content:
- **Spaces**: Only spaces where `owner = tenant user ID`
- **Posts**: Only posts where `author = tenant user ID` or `space.owner = tenant user ID`
- **Pages**: Only pages where `createdBy = tenant user ID`

## Setup

### Development (localhost)

#### Option 1: Hosts File (Manual)

Edit `/etc/hosts` (Mac/Linux) or `C:\Windows\System32\drivers\etc\hosts` (Windows):

```
127.0.0.1 username.localhost
127.0.0.1 anotheruser.localhost
```

#### Option 2: Wildcard DNS (Recommended)

Use a tool like `dnsmasq` or `local-ip.co`:

```bash
# Install dnsmasq (Mac)
brew install dnsmasq

# Configure
echo 'address=/.localhost/127.0.0.1' >> /usr/local/etc/dnsmasq.conf
sudo brew services start dnsmasq
```

Or use `local-ip.co` which provides wildcard DNS:
- `username.local-ip.co` → Your local IP

### Production

1. **Configure Wildcard DNS**
   ```
   *.yourdomain.com → Your server IP
   ```

2. **Wildcard SSL Certificate**
   - Use Let's Encrypt with DNS challenge
   - Or use a service like Cloudflare

3. **Update Environment Variables**
   ```env
   NUXT_PUBLIC_SITE_URL=https://yourdomain.com
   NUXT_PUBLIC_PAYLOAD_URL=http://localhost:3002
   ```

## Usage

### Access Tenant Admin

1. Visit `username.localhost:3000/admin/cms`
2. System extracts `username` from subdomain
3. Resolves to Payload user ID
4. Proxies to Payload with tenant context
5. Payload filters content automatically

### Access Main Admin

1. Visit `localhost:3000/admin/cms` (or main domain)
2. No tenant context
3. Full admin access (if user has admin role)

## Reserved Subdomains

These subdomains are **not** treated as tenant usernames:

- `www`
- `api`
- `admin`
- `app`
- `cdn`
- `static`
- `assets`
- `mail`

## Security Considerations

1. **Authentication**: Users must authenticate to access their tenant
2. **Access Control**: Payload access control enforces tenant isolation
3. **Cookie Domain**: Set cookies for `.localhost` (dev) or `.yourdomain.com` (prod) for cross-subdomain auth
4. **CORS**: Payload must accept requests from subdomains

## Troubleshooting

### Tenant Not Found

**Error**: `Tenant "username" not found in Payload CMS`

**Solution**:
1. Ensure user exists in AdonisJS with username
2. Ensure user is synced to Payload via `PayloadUserSyncService`
3. Check that `payloadUserId` is set in AdonisJS user record

### Subdomain Not Working

**Issue**: Subdomain not detected

**Solution**:
1. Check DNS/hosts file configuration
2. Verify middleware is running (check server logs)
3. Ensure subdomain is not in reserved list

### Payload Access Denied

**Issue**: User can't access their tenant content

**Solution**:
1. Verify Payload user exists and matches AdonisJS user
2. Check Payload access control rules
3. Ensure user has proper role (writer, editor, etc.)

## Overview

This project uses a **hybrid API architecture** that leverages the strengths of
both Nuxt Server API (Nitro) and AdonisJS API Gateway.

## Architecture Decision

### Why Hybrid?

1. **Performance**: Direct Payload REST API connections for public content
   (faster, less hops)
2. **Security**: Centralized authentication through AdonisJS for sensitive
   operations
3. **Flexibility**: Use the right tool for each use case

## Route Distribution

### 🟢 Nuxt Server API (Nitro) Routes

**Path**: `/api/*` (served by Nuxt at port 3000)

**Use for**: Public, read-only content

| Endpoint                | Purpose            | Authentication |
| ----------------------- | ------------------ | -------------- |
| `GET /api/posts`        | Blog posts list    | None (public)  |
| `GET /api/posts/[slug]` | Single blog post   | None (public)  |
| `GET /api/pages/one`    | Page content       | None (public)  |
| `GET /api/site-data`    | Site configuration | None (public)  |
| `GET /api/sitemap`      | XML sitemap        | None (public)  |
| `GET /api/search`       | Content search     | None (public)  |

**Implementation**: `apps/web/server/api/*.ts`

**Payload REST API**: Direct connection using native `fetch`

```typescript
// Example: apps/web/server/api/posts/index.get.ts
export default defineEventHandler(async (event) => {
  const payloadUrl = useRuntimeConfig().public.payloadUrl;
  const response = await fetch(
    `${payloadUrl}/api/posts?where[status][equals]=published`,
    {
      headers: {
        'Content-Type': 'application/json',
      },
    }
  );
  const data = await response.json();
  return data;
});
```

### 🔵 AdonisJS API Gateway Routes

**Path**: Proxied through Nginx to AdonisJS (port 3333)

**Use for**: Authenticated operations and user-specific content

#### Authentication Routes

| Endpoint                    | Purpose           | Method |
| --------------------------- | ----------------- | ------ |
| `/api/auth/register`        | User registration | POST   |
| `/api/auth/login`           | User login        | POST   |
| `/api/auth/logout`          | User logout       | POST   |
| `/api/auth/me`              | Current user      | GET    |
| `/api/auth/change-password` | Change password   | POST   |

#### User Routes (Authenticated)

| Endpoint                            | Purpose                    | Method |
| ----------------------------------- | -------------------------- | ------ |
| `/api/user/me`                      | Get user profile           | GET    |
| `/api/user/me`                      | Update profile             | PATCH  |
| `/api/user/users`                   | List all users (admin)     | GET    |
| `/api/user/users/:id/toggle-status` | Toggle user status (admin) | PATCH  |

#### CMS Routes (Authenticated for write operations)

| Endpoint                               | Purpose        | Method |
| -------------------------------------- | -------------- | ------ |
| `/api/cms/collections/:collection`     | Get collection | GET    |
| `/api/cms/collections/:collection/:id` | Get item       | GET    |
| `/api/cms/*`                           | Create content | POST   |
| `/api/cms/*`                           | Update content | PATCH  |
| `/api/cms/*`                           | Delete content | DELETE |

**Note**: Backend uses Payload Local API (direct database access) for better
performance and multi-tenant context.

**Services**: Payload Local API (direct database access) or proxy through
AdonisJS services

```typescript
// Example: apps/backend/app/controllers/cms_proxy_controller.ts
export default class CmsProxyController {
  async getPosts({ response, auth }: HttpContext) {
    const user = auth.user!; // Already authenticated
    const payloadService = await PayloadService.getInstance();
    const posts = await payloadService.getItems('posts', {
      user,
      filter: { status: { equals: 'published' } },
    });
    return response.ok({ posts });
  }
}
```

## Decision Matrix

### When to Use Nuxt Server API (Nitro)?

✅ **YES** if:

- Content is public
- Read-only operation
- No authentication needed
- Used for SSR/SEO
- Blog, documentation, landing pages

❌ **NO** if:

- Requires authentication
- Write/update/delete operations
- User-specific content
- Admin operations

### When to Use AdonisJS Gateway?

✅ **YES** if:

- Requires authentication
- Write/update/delete operations
- User-specific content
- Admin operations
- Form submissions with validation
- Rate limiting needed

❌ **NO** if:

- Public read-only content
- Already cached/static
- SSR performance critical

## Security Considerations

### Nuxt Server API (Public)

- ⚠️ Assumes all content is public
- ⚠️ No authentication checks
- ✅ Can use Payload access control for basic protection
- ✅ Fast and efficient for public content

### AdonisJS Gateway (Authenticated)

- ✅ Centralized authentication
- ✅ Role-based access control
- ✅ Rate limiting
- ✅ Audit logging
- ✅ Token injection for backend services

## Migration Path

### Current State ✅

- Nuxt Server API for public Payload CMS content (REST API)
- AdonisJS for auth, user management, and authenticated CMS operations (Local
  API)

### Future Enhancements

1. Add caching layer to Nuxt Server API
2. Implement GraphQL endpoint in AdonisJS
3. Design provider-agnostic billing integration and webhook handlers
4. Implement real-time features with WebSockets

## Example: Form Submission Flow

### Public Contact Form

```
Browser → Nuxt Server API → Payload REST API
  POST /api/forms/submit
```

### Authenticated User Form

```
Browser → AdonisJS Gateway → Payload Local API
  POST /api/cms/user_submissions
  (includes user context for multi-tenant isolation)
```

## Billing Integration (Planned)

Provider-agnostic billing is not currently implemented. When introduced, the
integration should remain behind authenticated server-side services, with
validation, audit logging, rate limiting, and appropriate payment-data
handling.

## Performance Considerations

### Nuxt Server API

- **Latency**: ~10-50ms (direct connection)
- **Caching**: Nuxt auto-caching
- **SSR**: Optimized for server-side rendering

### AdonisJS Gateway

- **Latency**: ~50-100ms (one extra hop)
- **Benefits**: Authentication, validation, business logic
- **Caching**: Redis-based session and data cache

## Development Guidelines

### Adding a New Endpoint

#### Public Content?

1. Create in `apps/web/server/api/*.ts`
2. Use Payload REST API (fetch to `http://localhost:3002/api/*`)
3. No authentication needed
4. Test with `/api/*` URL

#### Authenticated Operation?

1. Create in `apps/backend/app/controllers/*.ts`
2. Add route in `apps/backend/start/routes.ts`
3. Use `middleware.auth()`
4. Test with authentication headers

## Summary

| Feature            | Nuxt Server API | AdonisJS Gateway          |
| ------------------ | --------------- | ------------------------- |
| **Purpose**        | Public content  | Authenticated operations  |
| **Authentication** | None            | Required                  |
| **Payload Access** | REST API        | Local API (direct DB)     |
| **Performance**    | Faster          | Slightly slower           |
| **Security**       | Basic           | Advanced                  |
| **Use Case**       | Blog, docs, SEO | User data and admin      |

---

**Rule of Thumb**: If it's on your marketing site, use Nuxt Server API. If it
requires login, use AdonisJS Gateway.
